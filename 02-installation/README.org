* 第二章：MOOSE 安装和环境配置

** 2.1 系统要求

*** 2.1.1 本仓库的最低运行前提

本教程仓库和“从零搭一个 MOOSE 开发环境”不是同一件事。对于本仓库，最低要求其实更直接：

- **必须有一个可运行的 MOOSE 可执行文件**
  - 优先使用 `combined-opt`
  - 或者 `moose-opt`
  - 或者通过环境变量 `MOOSE_LOCAL_BIN` 指定
- **必须有 Python 3**
- **推荐安装 `pandas`、`matplotlib`、`numpy`**
  - 没有这些包时，主仿真仍可能运行成功
  - 但 `complete-simulation/` 下的后处理脚本会被跳过
- **只有在跑 Gmsh 流程时才需要 Gmsh**
- **只有在查看 `.e` 结果时才需要 ParaView**

换句话说，本仓库本身不负责编译一个新的 MOOSE app，它主要复用你已有的 MOOSE 环境。

*** 硬件要求
- **CPU**：x86_64 或 ARM64 架构
- **内存**：至少 8 GB RAM（推荐 16 GB 或更多）
- **硬盘**：至少 30 GB 可用空间
- **并行计算**：多核 CPU 或 HPC 集群

*** 软件要求
- **操作系统**：
  - Linux（Ubuntu 20.04+, CentOS 7+, Fedora 等）
  - macOS 10.15+
  - Windows 10+ (通过 WSL2)
- **编译器**：
  - GCC 9.0.0 - 13.3.1
  - Clang 14.0.6+
- **Python**：3.10 或更高版本
- **必需的 Python 包**：
  - packaging
  - pyyaml
  - jinja2

** 2.2 安装方法概述

MOOSE 提供多种安装方法：

1. **Conda 安装**（推荐新手）：最简单，适合学习
2. **预编译二进制包**：快速开始，适合培训
3. **Docker 容器**：环境隔离，适合快速测试
4. **源代码编译**：完全控制，适合开发者

*** 2.2.1 针对本仓库的推荐选择

如果目标只是“先把教程跑起来”，建议这样选：

1. **已有可用 MOOSE 环境**：直接跳到本章的仓库级自检
2. **第一次接触 MOOSE**：优先考虑 Conda 或官方推荐安装方案
3. **需要自己开发模块或长期维护环境**：再考虑源码编译

不要把“学习教程”与“搭完整开发栈”捆绑成同一个起步动作，否则排错成本会明显上升。

** 2.3 方法一：使用 Conda 安装（推荐）

*** 2.3.1 安装 Miniconda

#+begin_src bash
# 下载 Miniconda（Linux x86_64）
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh

# 运行安装程序
bash Miniconda3-latest-Linux-x86_64.sh

# 按提示完成安装，重启终端
#+end_src

*** 2.3.2 创建 MOOSE 环境

#+begin_src bash
# 添加 conda-forge 频道
conda config --add channels conda-forge
conda config --set channel_priority strict

# 创建专用环境
conda create -n moose python=3.11

# 激活环境
conda activate moose

# 安装 MOOSE
conda install moose-dev
#+end_src

*** 2.3.3 验证安装

#+begin_src bash
# 检查 MOOSE 版本
moose --version

# 运行测试
cd $CONDA_PREFIX/share/moose/test
make -j4
./run_tests -j4
#+end_src

*** 2.3.4 安装完成后，用本仓库做一次自检

完成安装后，先不要直接进入复杂示例，先确认本仓库能找到你的 MOOSE：

#+begin_src bash
cd /path/to/moose-tutorial

# 检查 MOOSE 可执行文件
command -v combined-opt || command -v moose-opt || echo "需要设置 MOOSE_LOCAL_BIN"

# 检查 Python 版本和可选后处理依赖
python3 --version
python3 -c "import pandas, matplotlib, numpy" || echo "后处理依赖尚未安装"

# 运行第一个轻量示例
cd 04-first-example/examples
../../run_moose_local.sh -i cantilever_beam.i
#+end_src

如果这一步能跑通，再进入完整流程目录。

** 2.4 方法二：从源代码编译

*** 2.4.1 安装依赖

**** Ubuntu/Debian
#+begin_src bash
# 更新系统
sudo apt-get update

# 安装基本工具
sudo apt-get install -y \
  build-essential \
  gfortran \
  tcl \
  git \
  m4 \
  freeglut3 \
  doxygen \
  libblas-dev \
  liblapack-dev \
  libx11-dev \
  libnuma-dev \
  libcurl4-openssl-dev \
  zlib1g-dev \
  libhwloc-dev \
  libxml2-dev \
  libpng-dev

# 安装 Python 和包
sudo apt-get install -y python3 python3-dev python3-pip
pip3 install packaging pyyaml jinja2
#+end_src

**** macOS
#+begin_src bash
# 使用 Homebrew 安装依赖
brew install \
  gcc \
  open-mpi \
  cmake \
  python@3.11

# 安装 Python 包
pip3 install packaging pyyaml jinja2
#+end_src

*** 2.4.2 克隆 MOOSE 源代码

#+begin_src bash
# 创建工作目录
mkdir -p ~/projects
cd ~/projects

# 克隆 MOOSE 仓库
git clone https://github.com/idaholab/moose.git
cd moose

# 克隆子模块
git submodule update --init --recursive
#+end_src

*** 2.4.3 编译 PETSc

#+begin_src bash
cd ~/projects/moose
export MOOSE_DIR=$(pwd)

# 设置环境变量（添加到 ~/.bashrc）
echo "export MOOSE_DIR=$HOME/projects/moose" >> ~/.bashrc
source ~/.bashrc

# 编译 PETSc（需要 30-60 分钟）
./scripts/update_and_rebuild_petsc.sh
#+end_src

*** 2.4.4 编译 libMesh

#+begin_src bash
cd $MOOSE_DIR

# 编译 libMesh（需要 20-40 分钟）
./scripts/update_and_rebuild_libmesh.sh
#+end_src

*** 2.4.5 编译 MOOSE

#+begin_src bash
cd $MOOSE_DIR/test

# 编译（使用 4 个核心）
make -j4

# 运行测试验证
./run_tests -j4
#+end_src

*** 2.4.6 让本仓库复用你的本地 MOOSE

如果你的可执行文件不叫 `combined-opt` 或 `moose-opt`，推荐在运行本仓库时显式传入：

#+begin_src bash
cd /path/to/moose-tutorial
MOOSE_LOCAL_BIN=/path/to/moose_test-opt ./run_moose_local.sh -i complete-simulation/simple_demo.i
#+end_src

`run_moose_local.sh` 的查找顺序是：

1. `combined-opt`
2. `moose-opt`
3. `MOOSE_LOCAL_BIN`

这比在每个章节里手动替换命令更稳妥。

** 2.5 方法三：使用 Docker

*** 2.5.1 安装 Docker

#+begin_src bash
# Ubuntu
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# 将用户添加到 docker 组
sudo usermod -aG docker $USER

# 重新登录以应用更改
#+end_src

*** 2.5.2 拉取 MOOSE 镜像

#+begin_src bash
# 拉取官方镜像
docker pull idaholab/moose

# 运行容器
docker run -it -v $(pwd):/workspace idaholab/moose
#+end_src

如果你使用 Docker，建议把本仓库挂载进容器后，从仓库根目录运行文档中的命令；否则相对路径会和教程说明不一致。

** 2.6 创建第一个应用程序

本节适合想继续做 MOOSE 开发的人。如果你的目标只是学习本教程仓库里的输入文件和流程，可以先跳过，直接去第四章和 `complete-simulation/`。

*** 2.6.1 使用 Stork 脚本

#+begin_src bash
cd ~/projects

# 创建新应用（替换 MyApp 为你的应用名）
$MOOSE_DIR/scripts/stork.sh MyApp

# 进入应用目录
cd MyApp

# 查看目录结构
tree -L 2
#+end_src

*** 2.6.2 编译应用

#+begin_src bash
cd ~/projects/MyApp

# 编译（优化版本）
make -j4

# 编译（调试版本）
METHOD=dbg make -j4
#+end_src

*** 2.6.3 运行测试

#+begin_src bash
# 运行所有测试
./run_tests -j4

# 运行特定测试
./run_tests -i test_name
#+end_src

** 2.9 常见问题解决

*** 问题 1：编译失败 - 内存不足

**解决方案**：减少并行作业数
#+begin_src bash
make -j2  # 使用 2 个核心而不是 4 个
#+end_src

*** 问题 2：找不到 Python 包

**解决方案**：
#+begin_src bash
pip3 install --user packaging pyyaml jinja2
#+end_src

*** 问题 3：PETSc 编译错误

**解决方案**：
#+begin_src bash
cd $MOOSE_DIR/scripts
./update_and_rebuild_petsc.sh --skip-submodule-update
#+end_src

*** 问题 4：权限问题

**解决方案**：
#+begin_src bash
# 不要使用 sudo 编译 MOOSE
# 确保目录权限正确
chmod -R u+w ~/projects/moose
#+end_src

** 2.10 性能优化

*** 2.10.1 使用编译器优化

#+begin_src bash
# 使用优化编译（默认）
METHOD=opt make -j4

# 使用调试编译（开发时）
METHOD=dbg make -j4

# 使用性能分析编译
METHOD=pro make -j4
#+end_src

*** 2.10.2 配置并行计算

#+begin_src bash
# 使用 MPI 并行运行
mpiexec -n 4 ./myapp-opt -i input.i

# 使用线程并行
./myapp-opt -i input.i --n-threads=4
#+end_src
